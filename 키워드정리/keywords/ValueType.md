# Value Type

| **구분** | **핵심 내용** |
| --- | --- |
| **개념** | 데이터의 실제 값을 스택(Stack) 메모리에 직접 저장하는 데이터 타입 |
| **메모리 특징** | 변수가 스코프를 벗어나면 즉시 해제되며, 가비지 컬렉터(GC) 부담이 없음 |
| **할당/전달 방식** | 값 복사 (Copy by Value) — 한쪽 변수를 수정해도 다른 쪽에 영향을 주지 않음 |
| **Null 여부** | 기본적으로 `null` 불가 (`Nullable<T>` / `T?`를 사용하여 허용 가능) |
| **주요 종류** | • 기본 타입: `int`, `double`, `bool`, `char` 등<br>• 복합/사용자 정의: 구조체(`struct`), 열거형(`enum`), 튜플(`ValueTuple`) |
| **성능 고려사항** | • 박싱/언박싱: `object` 변환 시 히프 할당으로 성능 저하 발생<br>• 참조 전달: 복사 비용 절감을 위해 `ref`, `out`, `in` 키워드 활용 가능 |

## 정의

- 데이터의 실제 값을 스택(Stack) 메모리 영역에 직접 저장하는 데이터 타입

## 특징

- **스택(Stack) 메모리 활용 :** 대부분 스택에 직접 할당되어 생성과 소멸이 매우 빠름. (단, 클래스의 필드로 선언된 값 타입은 해당 클래스와 함께 히프에 위치함)
- **복사 전달 (Copy by Value) :** 변수를 다른 변수에 할당하거나 메서드 인자로 전달할 때 값이 복사됩니다. 한쪽을 수정해도 다른 쪽에 영향을 주지 않음.
- **Null 불가 :** 기본적으로 `null`을 가질 수 없음. (필요한 경우 `int?`와 같은 Nullable 타입으로 확장 사용)
- **자동 메모리 관리** : 변수가 선언된 블록(Scope)을 벗어나면 스택에서 즉시 메모리가 해제되므로 가비지 컬렉터(GC)의 부담을 주지 않는다.

## 종류

| **구분** | **종류 및 예시** | **특징** |
| --- | --- | --- |
| **기본 숫자 타입** | `int`, `long`, `float`, `double`, `decimal` 등 | 가장 흔히 쓰이는 기본 데이터 타입 |
| **기타 기본 타입** | `bool`, `char` | 참/거짓 및 단일 문자를 다루는 타입 |
| **구조체 (Struct)** | `DateTime`, `TimeSpan`, `Vector3`, 사용자 정의 `struct` | 관련 데이터들을 하나로 묶어 작은 객체처럼 다룰 때 사용 |
| **열거형 (Enum)** | `enum DayOfWeek { Sun, Mon, ... }` | 정수형 상수에 이름을 부여하여 코드 가독성을 높임 |
| **튜플 (Tuple)** | `(int x, int y) point = (10, 20);` | 임시로 여러 값을 묶어서 전달할 때 사용 (`ValueTuple`) |

## !주의!

#### 박싱(Boxing)/언박싱(Unboxing)

값 타입을 참조 타입(예: `object` 또는 인터페이스)으로 변환할 때 성능 저하가 발생할 수 있음.

- **박싱 :** 값 타입을 Heap 영역으로 옮겨 `object` 객체로 포장하는 과정 (메모리 할당 발생)
- **언박싱 :** 포장된 `object`에서 다시 값 타입으로 값을 추출하는 과정
